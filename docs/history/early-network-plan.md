# Kubric 频闪数据集与视频去频闪网络：首版研究设计

> 2026-09-16 范围更新：当前只考虑数据集。更完整、更新的数据生成依据见 [详细背景调研](/overview)。本文件保留早期网络假设，不作为本轮实施范围。

更新日期：2026-09-15。状态：背景梳理与设计草案；尚未生成数据、实现网络或运行训练。以下规模和结构是待验证的实验起点。

## 1. 背景与目标

背景来自任务「去除频闪」（019ed10b-af86-7c53-9d5b-76fb66d3422c）。实际需求是修复人像视频拍摄中的频闪，同时保留纹理与人物运动边缘。

历史任务记录中的结果：

- All-In-One-Deflicker 输出被反馈明显偏糊；短切片与 down=2/4 对比仍未解决。
- 全局亮度校正保留细节，但用户反馈频闪仍明显。
- 强局部亮度校正改善去闪，但用户反馈人物出现虚影。
- 这些是历史反馈，不代表已重新检查原视频或证实了虚影的单一成因。亮度波动和拉普拉斯等指标也不能单独证明恢复质量。

首版任务定义：输入一段受光源调制影响的 RGB 视频，输出相同时刻、相同运动、相同相机采样条件下，光源不发生快速调制时的视频。暂按离线处理设计。

保留物体运动、遮挡、移动阴影以及正常的慢速照明变化。配对真值保留与输入相同的曝光时长和滚动快门几何，避免把去闪、去运动模糊和几何矫正混成一个目标。

原片是否由灯光调制造成、是否存在逐行条带、是否涉及屏幕重拍，仍需原片诊断。当前以“灯光照射真实三维场景”的频闪为主要建模假设。

建议检验的研究假设：**按光源贡献和逐行曝光过程生成动态配对数据，能否改善多灯照明、遮挡边缘与连续视频上的真实泛化；显式光照校正能否在相同去闪强度下更好保留纹理。**

## 3. Kubric 的角色与需要补充的部分

[Kubric 官方仓库](https://github.com/google-research/kubric)提供场景、物理运动和渲染组织能力，以及深度、分割和光流等辅助输出。它适合作为数据生成底座。

源码核对发现：

1. 默认彩色输出使用 PNG，不能直接视为线性辐射值。需要从 EXR 提取线性颜色，并显式控制后续显示变换。[渲染器源码](https://github.com/google-research/kubric/blob/main/kubric/renderer/blender.py)
2. 当前 `motion_blur` 路径使用合成器矢量模糊；它不能替代这里所需的连续时间照明与逐行曝光积分。[辅助渲染源码](https://github.com/google-research/kubric/blob/main/kubric/renderer/blender_utils.py)

因此需要实现一个相机曝光合成层，并验证 Kubric/Blender 的子帧场景求值。不能只给每一帧灯光设一个关键帧，就称为物理曝光模拟。

实现前固定 Kubric 提交、Blender 版本、渲染设备、色彩设置及资源版本。旧环境与当前 GPU 的兼容性必须通过小场景实测，当前没有安装兼容性结论。

## 4. 先定义成像过程，再生成配对数据

### 4.1 时间与照明

设帧率为 F，曝光时长为 T，传感器首末行的曝光起始时间差为 τ。第 n 帧第 y 行的起始时间：

```text
t(n,y) = n/F + y/(H-1) × τ
```

坐标 y 指传感器扫描方向；旋转、裁切、缩放后的显示坐标需要保存映射。竖拍视频不能直接假定条带一定沿显示画面的横向。

将第 k 个光源表示为慢速亮度包络 b_k(u) 与快速调制 q_k(u) 的乘积；约定 q_k 在一个调制周期内均值为 1。设 A_k(p,u) 是时刻 u、像素 p 对单位强度光源 k 的线性响应，包含当前几何、材质、阴影与反射贡献：

```text
L_flicker(p,u) = Σ_k A_k(p,u) × b_k(u) × q_k(u)
L_clean(p,u)   = Σ_k A_k(p,u) × b_k(u)

X_n(p) = (1/T) ∫[t(n,y), t(n,y)+T] L_flicker(p,u) du
Y_n(p) = (1/T) ∫[t(n,y), t(n,y)+T] L_clean(p,u) du
```

RGB 通道可使用不同调制，但首版先使用同色调制，再增加混合色温与颜色频闪。恒定环境光可以作为 q=1 的独立光源分量。

X、Y 使用同一条运动轨迹、同一行曝光窗口和同一相机响应。先完成线性积分，再执行传感器曝光缩放、噪声、裁剪和相机颜色处理；首轮使用无噪声配对隔离频闪，后续分开增加噪声及压缩实验。

### 4.2 一个可验证的数值例子

对于理想单频正弦调制，设 F=30 fps、f=100 Hz、τ=15 ms、T=1 ms：

- 从首行到末行经历 fτ=1.5 个照明周期。
- 固定行跨帧采样时，100 Hz 分量混叠到 10 Hz。
- 曝光平均后的调制幅度乘以 sinc(fT)=sin(πfT)/(πfT)，此例约为 0.984。
- 若仅把 T 改成 10 ms，理想模型恰好积分一个完整周期，调制应消失。

此例用于合成器校验，不代表原视频灯频或曝光参数。有限帧率下可能有多个真实灯频产生相同观测，不应强制网络唯一恢复实际灯频。

### 4.3 两档合成精度

**快速版本：逐光源线性贡献图 + 解析曝光系数。**

在每帧参考时刻渲染独立光源贡献 A_k，并用解析或高精度一维积分计算各行光源系数，再在线性域组合。正弦调制可解析积分；PWM 可按开关时间区间积分。

这一近似忽略整帧读出与曝光期间的几何变化，仅在该期间运动位移足够小时使用。它适合首先验证多灯、局部照明与颜色调制，必须在元数据标记近似级别。

**精确版本：子帧光源贡献 + 逐行时间积分。**

在覆盖整帧所有行曝光窗口的多个时刻求值场景，按光源渲染线性贡献，再根据各行的曝光权重积累。同一批贡献可复用来生成多种调制参数。

时间采样密度根据运动与光源波形选择，验证加密采样后的收敛；不能把固定 8 个子帧用于所有频率和 PWM 占空比。解析计算快速光源调制权重可以降低高频下的采样成本。

光源贡献相加成立的前提是固定场景状态下的线性光传输。组合前关闭非线性后处理，并检查采样噪声、降噪器和饱和处理是否破坏配对。

## 5. 数据集设计

### 场景与退化覆盖

| 维度 | 首版覆盖 |
| --- | --- |
| 运动 | 静止、平移/旋转、遮挡显露、相机运动；后续加入人物关节与衣物运动 |
| 纹理与材质 | 细线、织物、头发相似细结构、肤色表面、漫反射与高光 |
| 光照 | 单灯、多灯不同相位、恒定环境光混合、局部阴影、正常慢速亮度变化 |
| 波形 | 正弦、带谐波波形、PWM；频率、幅度、占空比、相位可控 |
| 相机 | 帧率、曝光、读出时间、扫描方向；传感器方向与显示旋转分开保存 |
| 对照样本 | 无频闪、正常移动阴影、照明渐变；约束模型保留应当保留的变化 |

100/120 Hz 可作为初始测试点，不能用它们覆盖全部 LED/PWM。参数分布要结合真实素材诊断调整，物理参数组合需要满足目标相机采样约束。

简单几何体用于单元场景验证；真实人像泛化还需要更接近目标的材质、可动人物资产或干净真实视频合成补充。仅靠默认掉落物体场景不足以验证人像修复效果。

### 每条样本应包含

- 频闪输入、稳定照明真值；可保留线性版本及显示版本。
- 帧时间、曝光、读出、扫描方向、光源波形和随机种子。
- 场景/资产/运动标识、合成器版本、采样精度和颜色处理记录。
- 校正场或差分场、饱和与低信号掩码。
- 可选的深度、实例分割、运动对应和遮挡掩码，以及它们的时间定义。

默认 Kubric 光流不能未经验证直接当作曝光积分后的滚动快门真值。应重新计算与行时序一致的对应，或明确标记为参考时刻的近似辅助标签；遮挡处和曝光混合边缘不强制使用不可靠对应。

### 划分与规模

先划分场景/运动轨迹，再生成退化变体和训练裁块。同一原始轨迹的相邻片段、相位变体不能跨训练/验证/测试集合。

建议先跑 8 个可解释小场景检查成像，再做 100 条场景轨迹 × 32 帧 × 4 组退化，得到 12,800 对输出帧。可先按 80/10/10 条轨迹划分。此规模只用于验证流程，不足以证明研究结论；真正渲染成本还取决于光源数、子帧数和路径采样数。

后续独立增加未见资产、光源波形、相机参数及多灯组合的测试集。现有真实人像视频用于开发观察时，另外保留独立真实视频作为最终测试，避免反复调参后把开发素材称作泛化测试。

## 6. 网络设计：先做可解释基线

输入暂取连续 5 帧，恢复中心帧。该结构是设计假设，尚无效果结论。

```text
5 帧视频
  ├─ 单帧粗校正 → 光照变化估计
  ├─ 粗校正后的多帧特征 → 运动对齐与遮挡置信度 → 时间信息融合
  └─ 中心帧原分辨率通路 → 纹理与轮廓保留
                          ↓
                校正场预测 + 有限残差修复
                          ↓
                    中心帧恢复结果
```

建议将校正场分成全局、沿扫描方向的条带、二维局部三部分：

```text
G_n(x,y) = g_global(n) + g_band(n,y) + g_local(n,x,y)
Ŷ_n = I_n ⊙ exp(G_n) + M_n ⊙ R_n
```

I 是模型工作域中的中心帧，G 是直接把输入修正到目标的对数增益，R 是补充残差，M 控制残差使用范围。模型工作域及其与线性成像的关系必须明确：在线性合成版本可直接解释增益；真实成片存在未知 ISP 时，增益只是有效校正近似。

例如在线性域，某个未饱和像素输入为 0.20、目标为 0.25，则 G≈log(1.25)，零残差即可得到 0.25。若输入已接近零或发生截断，单靠乘法无法恢复丢失纹理，需要邻帧证据和置信度处理。

设计约束：

- 保留中心帧原分辨率通路；降低亮度估计分支分辨率不等于把全部细节降采样后重建。
- 条带分支保留扫描轴分辨率。二维局部分支考虑光照边界，避免过强平滑抹掉窄条带，也避免补偿场追随旧的人物轮廓。
- 对齐尽量使用粗校正后的特征；原始频闪条纹可能误导运动估计。
- 光流、遮挡与低置信度区域需要门控；原分辨率通路并不自动保证没有虚影。
- 合成真值的光流、深度等只用于训练辅助和诊断。真实推理不要求外部提供这些真值。
- 全局/条带/局部分解并非天然唯一；用零均值约束等减少分支互相替代，优先监督总校正场。

## 7. 损失函数与评估

首轮使用重建损失、梯度损失、有效区域的校正场监督，以及受遮挡掩码约束的时间损失；各项权重通过验证集确定。

时间损失应比较恢复序列与干净真值的变化是否一致，例如比较二者经过相同可靠对应后的帧间差分，而不是把所有帧强行拉到同一亮度。无频闪样本增加恒等约束，防止模型把正常运动阴影或照明变化抹掉。

合成测试同时检查：

- PSNR/SSIM 与感知距离，分层报告，不能只看平均值。
- 与干净真值相比的残余条带/亮度误差，按静态区域、运动区域和遮挡边缘分别分析。
- 细纹理与轮廓误差、饱和/暗部恢复、长期视频一致性。
- 推理耗时、显存、全分辨率或分块处理方式。

真实视频没有配对真值时，固定区域或跟踪区域的时空亮度图和频谱只是诊断工具；画面内容也会产生周期信号。结合盲评、相同裁切的运动边缘对比、纹理保真检查，不能用“整体亮度方差下降”作为成功的充分条件。

所有视频对比保持相同帧率、显示方向、分辨率和编码条件。

## 8. 最小实验矩阵与实施顺序

### 第一阶段：验证合成器

1. 单灯静态平面：与解析正弦曝光结果对比。
2. q=1 时输入与目标一致；τ=0 时不因逐行时间差产生条带。
3. 单灯完整周期曝光应消除理想周期调制。
4. 不同灯相位和照射区域产生不同局部响应。
5. 快速近似与子帧积分对照；增加采样检查收敛。
6. 输入与目标的轨迹、快门时序、裁切与颜色处理一致。

### 第二阶段：分开验证数据价值和网络价值

| 问题 | 对照方式 |
| --- | --- |
| 物理合成是否有效？ | 固定网络，比较整帧亮度扰动、二维条带合成、Kubric 多光源合成；控制训练样本量和训练预算 |
| 多帧是否有效？ | 固定数据，比较单帧校正和 5 帧融合 |
| 显式校正是否有效？ | 固定数据与近似容量，比较直接 RGB 残差和校正场结构 |
| 是否减少虚影？ | 对齐/遮挡门控开关消融，重点看运动轮廓与显露区域 |
| 辅助真值是否有效？ | 光流/几何辅助监督消融，推理接口保持一致 |

先建立普通 U-Net 或同等级网络的单帧/多帧基线，再引入候选结构；同时重点对照 Flickerformer，并使用 BurstDeflicker 的适用数据验证跨数据集表现。[Flickerformer 代码](https://github.com/qulishen/Flickerformer)、[BurstDeflicker 代码与数据入口](https://github.com/qulishen/BurstDeflicker)

### 第三阶段：真实域验证

诊断现有人像素材的静态背景、人物区域、条带方向和帧间变化。记录仍不确定的曝光/读出/灯频，不能从视频文件帧率直接推算快门时长。依据观测校准合成分布，再在独立真实视频上测试。

首个实际交付目标：可复现的小场景生成器、成对样片、成像校验结果、基础网络的小规模训练结果，以及真实视频同条件对比。验证该闭环后再扩展人物资产和数据规模。
